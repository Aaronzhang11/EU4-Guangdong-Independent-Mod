## 1. 目标与适用范围

本流程用于在 Europa Universalis IV 地图模组中增加新的不可通行山脉省份。

它解决以下任务：

- 使用新的省份颜色绘制山体；
- 切断指定省份之间的直接道路；
- 保留山口、河谷或其他通行走廊；
- 将新山体登记为不可通行省份；
- 检查山体连通、地图格式和省份邻接；
- 在游戏中验证军队寻路。

不可通行判定由 `map/climate.txt` 的 `impassable` 列表负责。`terrain.bmp` 和 `terrain.txt` 主要负责地形分类与外观，不能代替不可通行登记。

## 2. 前置安全检查

开始前：

1. 定位模组根目录；
2. 确认其中存在 `descriptor.mod` 和 `map/provinces.bmp`；
3. 运行 `git status --short`；
4. 记录当前未提交修改；
5. 确认用户允许修改的目录；
6. 不修改 Steam 安装目录；
7. 不直接在启动器模组副本中开发；
8. 不使用 `git reset --hard` 或其他破坏性清理命令。

正式地图文件为：

```text
<mod-root>/map/provinces.bmp
```

候选图、PSD、截图和规划文件不能代替正式地图。

## 3. 设计通行关系

绘图前建立邻接表。

至少记录：

| 类型 | 含义 |
|---|---|
| 阻断邻接 | 绘制后两省公共边必须为零 |
| 保留邻接 | 绘制后两省仍须保留正交公共边 |
| 不关心邻接 | 可以随地图形状自然变化 |
| 山体内部连接 | 同一山体必须上下左右四向连通 |

必须遵守：

- 保留通道时，不依赖对角像素；
- 山口应保留多条连续公共边；
- 不相连的山体段分别使用不同省份 ID；
- 不使用同一颜色制造多个无关飞地；
- 除非确有真实山口依据，否则不要用特殊邻接代替自然通道；
- 普通陆地道路由 `provinces.bmp` 的自然接壤决定。

## 4. 分配省份 ID 与 RGB

读取：

```text
map/definition.csv
map/default.map
map/provinces.bmp
```

### 4.1 ID 规则

- 选择当前未使用的省份 ID；
- 建议同一批次连续编号；
- 不提前登记尚未绘制的未来 ID；
- `max_provinces` 必须等于最高正式省份 ID 加一。

示例：

```text
最高正式 ID：5311
max_provinces = 5312
```

### 4.2 RGB 规则

每个新山体需要唯一 RGB：

- 三通道范围均为 `0–255`；
- 不与 `definition.csv` 中现有颜色重复；
- 不与 `provinces.bmp` 中现有颜色重复；
- 不使用抗锯齿生成的近似色；
- 一旦开始正式绘制，不随意更换颜色。

定义格式：

```text
<ID>;<R>;<G>;<B>;<English Name>;x
```

示例：

```text
5310;37;173;211;Nanling West;x
5311;198;52;122;Nanling East;x
```

> **原版重复RGB例外：** 部分原版RNW随机新大陆占位省份可能包含历史重复RGB。
> 不要为了山脉批次修改这些既有定义。审计时应把既有重复项记录为警告，但新增山脉
> RGB仍不得与任何现有省份颜色冲突。

## 5. 创建并绘制候选地图

复制正式地图作为未修改备份：

```text
planning/<batch>/candidate_baseline.bmp
```

创建版本化候选图：

```text
planning/<batch>/candidate_v1.bmp
planning/<batch>/candidate_v2.bmp
```

绘图要求：

- 尺寸保持 `5632 × 2048`；
- 使用 RGB；
- 使用24位BMP；
- 使用无压缩 `BI_RGB`；
- 禁止透明通道；
- 禁止抗锯齿；
- 禁止缩放和重采样；
- 每段山体形成一个四向连通块；
- 避免单像素飞地；
- 避免单像素长颈；
- 不切走旧省的城市、港口或其他位置锚点。

使用 Photoshop 时，读取：

```text
references/photoshop.md
```

## 6. 几何与邻接审计

候选图绘制完成后，先进行只读检查，不立即覆盖正式地图。

### 6.1 BMP检查

确认：

- 文件签名为BMP；
- 宽度为5632；
- 高度为2048；
- 位深为24位；
- 压缩方式为0；
- 模式为RGB；
- 没有未经登记的新颜色。

### 6.2 山体检查

对每个新增山体检查：

- RGB是否正确；
- 像素数量是否大于零；
- 是否只有一个四向连通块；
- 是否存在单像素飞地；
- 是否存在容易断裂的长颈；
- 山体宽度是否足以稳定显示；
- 是否误触海区。

### 6.3 邻接检查

对设计表逐项检查：

- 阻断邻接的公共边数量必须为零；
- 保留邻接必须仍有正交公共边；
- 山口不应只剩一个脆弱像素；
- 受影响旧省仍应各自保持连通；
- 不应出现未计划的跨山捷径；
- 不应意外围死可通行省份。

若存在 `scripts/audit_mountain.py`，优先使用其只读模式输出检查报告。

## 7. 写入正式地图

只有在候选图通过审核并取得用户同意后，才用候选图覆盖：

```text
map/provinces.bmp
```

覆盖前保留：

- 未修改基线；
- PSD工作文件；
- 最近一个能够进入游戏的BMP版本。

正式图写入后，不要继续在旧候选文件上无记录地修改。

## 8. 配套文件登记

每个新增不可通行山体都需要登记到以下文件。

### 8.1 `map/definition.csv`

添加ID与RGB：

```text
5310;37;173;211;Nanling West;x
5311;198;52;122;Nanling East;x
```

### 8.2 `map/default.map`

设置：

```text
max_provinces = 最高正式省份ID + 1
```

### 8.3 `map/climate.txt`

在：

```text
impassable = {
}
```

内部添加山体ID：

```text
5310
5311
```

这是不可通行功能的核心登记。

### 8.4 `map/continent.txt`

把山体加入正确大陆，例如：

```text
asia = {
    5310 5311
}
```

### 8.5 `map/terrain.txt`

在 `mountain` 的 `terrain_override` 中加入山体ID：

```text
mountain = {
    terrain_override = {
        5310 5311
    }
}
```

不要把省份ID误加到后面的 `impassable_mountains = {}` 地形类型定义中。

### 8.6 `terrain.bmp`

第一轮功能测试可以暂不修改 `terrain.bmp`。

后续外观细化时：

- 使用调色板山地索引；
- 不改变图像尺寸；
- 不把不可通行逻辑寄托在地形贴图上；
- 南方山地一般不使用雪峰索引；
- 保持山麓和山脊的自然过渡。

## 9. 不需要创建的内容

不可通行山脉通常不创建：

- `history/provinces/<ID> - Name.txt`；
- 所有者；
- 核心；
- 文化；
- 宗教；
- 商品；
- 发展度；
- `positions.txt` 条目；
- Area成员；
- Region成员；
- 贸易节点成员；
- 贸易公司成员；
- 普通特殊邻接。

如果山体被错误加入Area或贸易系统，应将其移除。

## 10. 本地化

在可读UTF-8本地化源中加入：

```text
PROV5310:0 "南岭西段"
PROV_ADJ5310:0 "南岭西段"
PROV5311:0 "南岭东段"
PROV_ADJ5311:0 "南岭东段"
```

然后运行项目的本地化编码器，例如：

```powershell
python .\tools\encode_eu4_chinese_localisation.py
```

不要直接手工输入双字节编码本地化。

检查：

- 可读源正常显示中文；
- 生成的YML带正确BOM；
- 编码器能够往返验证；
- 游戏内不显示 `PROV5310` 等缺失键。

## 11. 游戏测试

先确认启动器实际读取的模组目录。

如果仓库目录和启动器目录不是链接：

- 明确告知用户需要同步；
- 未经授权，不自动写入启动器目录；
- 不修改Steam原版文件。

测试步骤：

1. 完全退出游戏；
2. 同步测试模组；
3. 重新启动；
4. 创建新的1444年游戏；
5. 打开控制台；
6. 输入 `debug_mode`；
7. 悬停确认山体ID和名称；
8. 确认军队不能进入山体；
9. 测试所有阻断道路；
10. 测试所有保留山口；
11. 检查周边省份是否仍能正常寻路；
12. 检查 `error.log` 和 `map.log`。

不要使用旧存档验证地图结构变化。

## 12. 回退与版本控制

测试失败时，使用保存的基线恢复 `map/provinces.bmp`。

回退时同时恢复：

- `definition.csv`；
- `default.map`；
- `climate.txt`；
- `continent.txt`；
- `terrain.txt`；
- 本地化源与生成文件。

提交前运行：

```powershell
git status --short
git diff --stat
```

不要使用：

```text
git add .
```

只暂存本批次明确相关的文件。

## 13. 南岭实例

本次南岭练习使用：

| ID | 名称 | RGB | 十六进制 |
|---:|---|---|---|
| 5310 | 南岭西段 | `37,173,211` | `#25ADD3` |
| 5311 | 南岭东段 | `198,52,122` | `#C6347A` |

正式登记：

```text
5310;37;173;211;Nanling West;x
5311;198;52;122;Nanling East;x
```

最大省份数：

```text
max_provinces = 5312
```

不可通行登记：

```text
impassable = {
    5310 5311
}
```

该实例只作为示范。其他地图项目必须重新读取当前ID、RGB、邻接和模组目录，不得机械复用5310与5311。
